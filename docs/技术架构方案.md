# Meet-God 技术架构方案

> 版本：v1.0
> 日期：2026-06-22
> 平台：Windows（初期）
> 技术栈：Tauri 2 + Rust + React + TypeScript

---

## 一、项目定位

**Meet-God** 是一款开源的 AI 面试辅助桌面应用。核心能力：实时捕获系统音频 → 语音转文字 → AI 生成参考答案 → 悬浮窗展示。

**核心设计原则：**
1. **极致隐蔽** — 屏幕共享、截图、录屏均不可见
2. **用户自配** — 不内置任何后端服务，所有 API 由用户自行配置
3. **本地优先** — 内置 Whisper 本地模型，零网络依赖可用
4. **低延迟** — 端到端响应 < 2 秒

## 三、核心模块设计

### 3.1 音频捕获模块 (audio)

**技术方案：WASAPI Loopback + cpal 库**

```
系统音频输出 (扬声器/耳机)
        │
        ▼
  WASAPI Loopback 捕获 (无需虚拟声卡)
        │
        ├──► 音频流 (f32 PCM, 48kHz, 2ch)
        │        │
        │        ▼
        │    VAD 静音检测 (webrtc-vad)
        │        │
        │        ▼
        │    语音片段切分 (2-3s 一段, 重叠 0.5s)
        │        │
        │        ▼
        └──► 送入 STT 引擎
```

**核心依赖：**
```toml
[dependencies]
cpal = "0.15"                    # 跨平台音频库，支持 WASAPI
windows = { version = "0.56", features = [
    "Win32_Media_Audio",
    "Win32_Media_Audio_Endpoints",
]}                               # Windows API 绑定
```

**关键实现要点：**
- 使用 cpal 的 `default_output_device()` 获取默认音频输出设备
- 通过 `build_input_stream_raw()` 以 Loopback 模式捕获系统音频
- 音频格式：f32 采样、单声道降混（双声道取平均）、16kHz（Whisper 要求）
- 内置 VAD（Voice Activity Detection）过滤静音段，减少无效 STT 调用

**进阶功能（Phase 2+）：**
- 支持选择特定应用的音频会话（通过 WASAPI Session 级别 API）
- 可选麦克风通道，用于录制用户自己的回答

### 3.2 语音识别模块 (stt)

**方案：本地 Whisper + 云端 API 双模式，统一接口抽象**

```
┌─────────────────────────────────────────┐
│            STT Provider 接口             │
├─────────────────────────────────────────┤
│  trait SttProvider {                     │
│      fn transcribe(                      │
│          &self,                          │
│          audio: &[f32],                  │
│          sample_rate: u32,               │
│      ) -> Result<Transcription>;         │
│  }                                       │
│                                          │
│  struct Transcription {                  │
│      text: String,          // 识别文本   │
│      confidence: f32,       // 置信度     │
│      language: String,      // 语言       │
│      duration_ms: u64,      // 音频时长   │
│      latency_ms: u64,       // 识别耗时   │
│  }                                       │
└─────────────────────────────────────────┘
         │              │              │
    ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
    │ Whisper │    │ OpenAI  │    │  讯飞   │
    │ 本地    │    │ Whisper │    │  语音   │
    │ (默认)  │    │  API    │    │  API    │
    └─────────┘    └─────────┘    └─────────┘
```

**本地 Whisper 实现：**
- 使用 `whisper-rs`（Whisper.cpp 的 Rust 绑定）
- 默认模型：`ggml-base.bin`（~150MB，中文准确率高，延迟适中）
- 首次启动时自动下载模型文件到应用数据目录
- 模型加载到内存后常驻，避免重复加载开销
- 运行在独立线程，不阻塞 UI 和音频捕获

**云端 API 实现：**
- OpenAI Whisper API：标准 REST 调用，音频数据以 multipart/form-data 上传
- 讯飞语音听写：WebSocket 长连接，流式识别
- 统一超时控制和错误重试机制

**STT 配置项：**
```yaml
stt:
  provider: "whisper-local"      # whisper-local | openai | xunfei
  # 本地 Whisper 配置
  local:
    model: "base"                # tiny | base | small | medium
    language: "zh"               # 强制语言，留空自动检测
    device: "cpu"                # cpu | cuda
  # 云端 API 配置
  api:
    api_key: ""
    api_url: ""                  # 自定义 endpoint
    model: "whisper-1"
    timeout_ms: 10000
```

### 3.3 LLM 调度模块 (llm)

**方案：统一接口，多 Provider 插件化**

```
┌─────────────────────────────────────────────┐
│              LLM Provider 接口               │
├─────────────────────────────────────────────┤
│  trait LlmProvider {                         │
│      fn chat_stream(                         │
│          &self,                              │
│          messages: &[Message],               │
│          config: &ChatConfig,                │
│      ) -> Pin<Box<dyn Stream<Item = String>>>│
│  }                                           │
│                                              │
│  struct Message {                            │
│      role: Role,         // system/user/ai   │
│      content: String,                        │
│  }                                           │
│                                              │
│  struct ChatConfig {                         │
│      model: String,                          │
│      temperature: f32,                       │
│      max_tokens: u32,                        │
│      system_prompt: String,                  │
│  }                                           │
└─────────────────────────────────────────────┘
         │         │         │         │
    ┌────┴──┐ ┌────┴──┐ ┌───┴────┐ ┌──┴─────┐
    │OpenAI │ │Claude │ │通义千问 │ │Ollama  │
    │兼容API│ │  API  │ │DeepSeek│ │本地模型 │
    └───────┘ └───────┘ └────────┘ └────────┘
```

**关键设计：**

1. **OpenAI 兼容格式为标准** — 国内大部分模型（通义千问、DeepSeek、智谱、月之暗面）都兼容 OpenAI API 格式，只需切换 `api_url` 和 `api_key`
2. **流式输出（SSE）** — 使用 `reqwest` 的流式响应，逐 token 推送前端，实现打字机效果
3. **请求去重** — 相同问题短时间内不重复请求
4. **超时降级** — 主模型超时后自动切换备选模型

**System Prompt 设计：**
```
你是一位资深面试官助理。当求职者在面试中被提问时，你需要：
1. 快速理解面试官的问题意图
2. 生成结构清晰、要点明确的参考答案
3. 如果是技术问题，提供代码示例
4. 如果是行为面试问题，使用 STAR 法则组织答案
5. 答案控制在 200 字以内，便于快速阅读

当前简历信息：{resume_content}
当前岗位描述：{job_description}
```

**LLM 配置项：**
```yaml
llm:
  primary:
    provider: "openai"           # openai | claude | qwen | deepseek | ollama
    api_key: "sk-xxx"
    api_url: "https://api.openai.com/v1"
    model: "gpt-4o-mini"
    temperature: 0.7
    max_tokens: 1024
    timeout_ms: 15000
  fallback:                      # 主模型超时时的备选
    provider: "deepseek"
    api_key: ""
    api_url: "https://api.deepseek.com/v1"
    model: "deepseek-chat"
  local:                         # Ollama 本地模型配置
    api_url: "http://localhost:11434"
    model: "qwen2:7b"
```

### 3.4 隐蔽控制模块 (stealth)

**这是 Meet-God 的核心差异化能力。**

#### 3.4.1 窗口对屏幕共享不可见

```
Windows API 调用链：

SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)
    │
    ├── 屏幕共享软件（腾讯会议、飞书、Zoom）看不到此窗口
    ├── Windows 截图（Win+Shift+S）看不到此窗口
    ├── 录屏软件看不到此窗口
    └── 但用户自己在屏幕上能看到此窗口（正常显示）
```

**实现方式：**
```rust
use windows::Win32::UI::WindowsAndMessaging::{
    SetWindowDisplayAffinity, WDA_EXCLUDEFROMCAPTURE
};

// Tauri 窗口创建后设置
fn hide_from_capture(hwnd: HWND) {
    unsafe {
        SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE).unwrap();
    }
}
```

> 注意：`WDA_EXCLUDEFROMCAPTURE` 需要 Windows 10 2004 (Build 19041) 及以上版本。
> 对于更老的系统，回退到 `WDA_MONITOR`（窗口变黑，不完全理想）。

#### 3.4.2 窗口行为控制

| 功能 | 实现方式 | 说明 |
|------|---------|------|
| 始终置顶 | `SetWindowPos(HWND_TOPMOST)` | 答案窗口始终在最上层 |
| 不抢焦点 | 创建时使用 `WS_EX_NOACTIVATE` | 悬浮窗不抢走面试窗口焦点 |
| 无任务栏图标 | `WS_EX_TOOLWINDOW` 窗口样式 | 任务栏不显示 |
| 全局快捷键 | `RegisterHotKey` | 自定义显示/隐藏切换 |
| 系统托盘 | Tauri 内置 tray 功能 | 最小化到托盘，右键菜单 |
| 快速隐藏 | 双击 Esc 或自定义快捷键 | 瞬间隐藏所有窗口 |

#### 3.4.3 快捷键设计

| 快捷键 | 功能 | 说明 |
|--------|------|------|
| `Ctrl+Shift+H` | 显示/隐藏答案窗 | 主开关 |
| `Ctrl+Shift+M` | 静音/取消静音音频捕获 | 临时暂停 |
| `Ctrl+↑/↓` | 调整答案窗透明度 | 降低存在感 |
| `Ctrl+Shift+Esc` | 紧急退出 | 一键关闭应用 |

#### 3.4.4 界面隐蔽设计

- 悬浮窗支持**自由调节透明度**（10%-100%）
- 悬浮窗支持**自由调节大小和位置**，可拖拽到屏幕边缘
- 可选**极简模式**：只显示纯文字，无边框无标题栏，看起来像便签
- 界面中不出现"面试"、"AI"、"Copilot"等敏感词汇，使用隐晦命名

### 3.6 数据流管线 (pipeline)

**端到端数据流：**

```
[系统音频] ──WASAPI──► [音频缓冲区] ──VAD──► [有效语音片段]
                                                    │
                                                    ▼
                                           [STT 语音识别]
                                                    │
                                                    ▼
                                           [识别文本 + 上下文]
                                                    │
                                           ┌────────┴────────┐
                                           ▼                  ▼
                                    [LLM 生成答案]    [保存到面试记录]
                                           │
                                           ▼
                                    [流式推送前端]
                                           │
                                           ▼
                                    [悬浮窗渲染答案]
```

**延迟预算分配：**

| 环节 | 目标延迟 | 实现策略 |
|------|---------|---------|
| 音频捕获 → VAD | < 50ms | 系统级 API，零拷贝 |
| VAD → STT | < 100ms | 内存直传，无序列化 |
| STT 识别 | 300-500ms | Whisper base 本地推理 |
| STT → LLM | < 50ms | 异步立即触发 |
| LLM 首 token | 300-800ms | 流式输出 |
| LLM → 渲染 | < 50ms | WebSocket 推送 |
| **总计** | **700ms - 1.5s** | — |

### 3.7 面试记录模块 (recorder)

- 每次面试自动创建会话记录
- 存储格式：SQLite 数据库 (`%APPDATA%/meet-god/data/sessions.db`)
- 记录内容：
  - 识别文本（面试官问题 + 用户回答）
  - AI 生成的参考答案
  - 时间戳、时长
  - 用户标记（重要/已掌握/需复习）
- 支持导出为 Markdown / JSON
- 支持回放音频片段（如果开启了音频录制）

## 七、技术风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| WASAPI Loopback 在部分声卡上不工作 | 音频捕获失败 | 提供麦克风采集作为降级方案 |
| whisper-rs 编译困难（跨平台） | 开发受阻 | 使用预编译二进制，或改用 whisper.cpp 命令行调用 |
| `WDA_EXCLUDEFROMCAPTURE` 低版本不支持 | 隐蔽性降级 | 回退到 `WDA_MONITOR`，或提供"副设备方案"引导 |
| 部分会议软件使用加密音频流 | 无法捕获 | WASAPI 是系统级输出，应用层加密不影响 |
| Whisper 本地推理 CPU 占用高 | 影响面试软件性能 | 提供模型大小选择（tiny 最轻量），支持 GPU 加速 |
| LLM API 网络不稳定 | 答案延迟或失败 | 实现 fallback 机制 + 本地 Ollama 备选 |
